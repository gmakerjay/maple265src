# Progress Logging & Reporting Standard

เมื่อใดก็ตามที่มีการบันทึกความคืบหน้า (Progress) หรือรายงานสรุปการแก้ไขระบบ/Commit ให้ใช้รูปแบบและโครงสร้างประโยคตามมาตรฐานนี้เสมอในทุก Session:

## 1. ต้องระบุเวลาที่แก้ไขเสมอ (Timestamp Requirement)
- ทุกรายการต้องมีทั้ง **วันที่** และ **เวลาจริง (เช่น 22:51 น. หรือ HH:mm น.)**
- หากเป็น Git Commit ให้อ้างอิงเวลาของ Commit และย่อแฮช (เช่น `34c9857 (22:51 น.)`)

## 2. รูปแบบโครงสร้างหัวข้อและการเรียบเรียง (Standard Layout & Phrasing)
ให้ใช้โครงสร้าง 2 ส่วนหลักที่กระชับ สละสลวย และชัดเจนทั้งเชิงเทคนิคและฟังก์ชันระบบเกม:

```markdown
### 1. `[Commit Hash หรือ รหัส]` ([เวลา เช่น 22:51 น.]) — [หัวข้อภาษาไทยที่กระชับและเข้าใจง่าย] ([หัวข้ออังกฤษ])
- **หัวข้อ**: `[Commit Subject หรือ Feature Scope]`
- **รายละเอียด**:
  - **[ระบบ/สายงานย่อย 1]**: อธิบายปัญหาที่พบ (Problem) -> สาเหตุเชิงเทคนิค -> วิธีแก้ (Fix/Implementation) -> ผลลัพธ์ (Outcome)
  - **[ระบบ/สายงานย่อย 2]**: แจกแจงรายละเอียดและเมคานิกของเกมที่อัปเดต
  - ทำลิงก์ไปยังไฟล์ที่แก้ไขเสมอ เช่น [`SkillConstants.java`](file:///...)
```

## 3. สไตล์การเรียบเรียงประโยค (Phrasing Style)
- ใช้ภาษาไทยเชิงวิชาชีพ สุภาพ อ่านง่าย จัดหมวดหมู่ชัดเจน
- ใช้ตัวหนาเน้นคำสำคัญ (เช่น **Universal Boss Entry**, **Zero-Install**, **OriginDebuff**)
- แจกแจงปัญหาและแนวทางแก้ไขอย่างตรงจุด ไม่คลุมเครือ

## 4. การซิงค์เอกสาร `PROGRESS.md`
- บันทึกการเปลี่ยนแปลงลงใน `v214 src/PROGRESS.md` และคัดลอกซิงค์มาที่ `PROGRESS.md` ที่รูทเสมอ
- ตั้งหัวข้อเป็น `## 📅 [YYYY-MM-DD HH:mm น.] [ชื่อฟีเจอร์/การแก้ไข]`
